# Portfolio Release Checklist

## Content

- [ ] Main README accurately reflects the current build
- [ ] Every completed phase contains verification evidence
- [ ] Planned work is clearly labeled as planned
- [ ] No claims exceed what has actually been implemented
- [ ] Journal and changelog are current

## Images

- [ ] Screenshots are readable
- [ ] Filenames follow the naming standard
- [ ] No credentials, tokens, public IPs, or private URLs are visible
- [ ] Photos are placed beside the relevant phase
- [ ] Alt text is included where practical

## Technical Quality

- [ ] Commands were tested
- [ ] Device names and mount paths are accurate
- [ ] Internal Markdown links work
- [ ] Mermaid diagrams render
- [ ] Backup language distinguishes RAID from backup
- [ ] Recovery steps are included for major services

## GitHub Presentation

- [ ] Repository description is concise
- [ ] Topics include `homelab`, `proxmox`, `docker`, `linux`, `networking`, and `cybersecurity`
- [ ] Project website is enabled after the Pages workflow succeeds
- [ ] A release tag is created for major milestones
- [ ] The strongest screenshot is used in LinkedIn or résumé material
